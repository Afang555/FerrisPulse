# 新电脑、新鼠标适配手册

适用于 FerrisPulse 的 Windows HID 鼠标适配。当前主仓库 `D:\github\mouse`，玄熊猫分支 `MetapandaMouse05`；其他电脑按用户指定目录工作。路径、设备实例和 USB 地址均需重新确认。

先读 [AGENTS.md](../AGENTS.md)、[工程规范](../AGENT_RULES.md)、[架构](../ARCHITECTURE.md)，再读 [缺陷与回归记录](metapanda-regressions.md)。已有玄熊猫参数见 [使用指南](metapanda-guide.md)。流程可复用，型号命令必须有本设备证据。

## 1. 建立设备卡

在新型号适配文档记录以下内容，未知项写未确认，不推测填充。

| 项目 | 内容 |
|---|---|
| 代码 | 仓库、分支、commit、未提交差异、主目录、实际运行 exe |
| 实物 | 品牌/完整型号、硬件版本、鼠标与接收器固件、官方程序版本和路径 |
| 连接 | 有线 / 2.4G / 蓝牙分别是否可用，各自 VID/PID |
| HID 集合 | 完整路径、MI/Col、UsagePage/Usage、Input/Output/Feature 长度、Report ID |
| 目标 | 电量、充电、选择已有档位、编辑档位数值、回报率、规则，逐项列出 |
| 基线 | 真实档位数、各档 X/Y、当前档、回报率、规则和自启动 |
| 能力证据 | 官方软件可选 / 抓包证实 / 独立回读 / 实际频率测量，分别记录 |
| 下一步 | 下一项单变量操作、待观察字段、预期结果、恢复方法 |

换接收器或切有线可能产生不同端点。完整 HID 路径是本机路由身份，不是跨电脑产品 ID；迁移规则需重新绑定端点及实际前台 exe 路径。

## 2. 新电脑环境恢复

### 代码与构建

1. 已有目录先检查 `git status`、`git diff`，保留现有修改，不覆盖或重置。
2. 新 clone 确认远程和分支。下例仅对应本次玄熊猫，不是所有鼠标的固定起点：

```powershell
& 'C:\Program Files\Git\cmd\git.exe' clone --branch MetapandaMouse05 --single-branch https://github.com/Afang555/FerrisPulse.git D:\github\mouse
```

3. Git 不在 PATH 时使用已安装完整路径。编译器默认 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，`build.bat` 有 32 位回退。执行 `cmd /c build.bat` 并检查退出码。
4. 项目保持 C# 5 / .NET Framework 4.0、零第三方运行时 DLL。诊断工具不等于产品依赖。修改的 `.cs` / `.ps1` / `.bat` / `.md` 保持 UTF-8 BOM，编译保留 `/codepage:65001`。
5. 写入失败先检查目录 ACL。本机曾只有管理员/System 可写；必要时仅授予当前用户项目目录所需修改权限，不放宽整个磁盘，不混淆 Windows ACL 和工具沙箱。
6. 区分源码、构建和实际进程。outputs 可能是旧快照；替换 exe 前正常退出托盘程序，启动后核对完整路径，自启动亦指向选定主目录。

只改文档无需装抓包工具或重启。已有适配在新电脑可用时先验证功能，不必重做全部逆向。

### 诊断工具

需要新协议证据时从官方来源获取 Wireshark / tshark、USBPcap，验证数字签名并记录版本。本次使用过 Wireshark 4.6.9、USBPcap 1.5.4.0；这是历史环境，不要求未来固定旧版。产品运行不依赖它们。

USBPcap 需管理员安装，首次安装后服务 RUNNING 也可能必须重启才有接口。先运行 `USBPcapCMD.exe --extcap-interfaces` 检查；无接口不能声称已开始捕获。需要重启时由用户在合适时间执行。

## 3. 只读发现与准确定位

- 用 `Get-PnpDevice -PresentOnly` 看在场设备。注册表 EnumUSB 含历史记录，不能单独证明在线。
- 对比插拔前后设备，分别记录鼠标、接收器、接口与各 HID collection。一个接收器通常包含多个集合，选错集合会超时。
- 从 HID attributes / caps 读取 VID/PID、Usage、Input/Output/Feature 长度。诊断脚本放 `tools/scratch/`，先只读枚举，不向未知端点遍历试写。
- 查询 `DEVPKEY_Device_Address`、`DEVPKEY_Device_Parent`、`DEVPKEY_Device_LocationPaths`，关联 USB 地址、总线和父设备。
- `USBPcapCMD.exe --extcap-interfaces` 枚举接口，再用 `--extcap-interface '\\.\USBPcapN' --extcap-config` 查看目标总线，N 来自现场结果。
- 本机 F5AC 曾位于 USBPcap2、地址 4；换电脑、重启、重新插拔后必须重查，不能硬编码。

产出应明确官方程序控制哪条路径、哪一集合；不能只有 VID/PID。共享 VID 的代工品牌尤其需要防止通用助手错误认领。

## 4. 单变量抓包

已有适配先收集本机 `%LocalAppData%\FerrisPulse\logs` 的事件及连续电量 CSV（托盘可打开），记录版本、连接方式、官方同一时段读数及多个采样。CSV 保留等级/电压/估算值/充电/DPI/回报率/耗时/报文，可先排除旧界面状态和粗粒度百分比。每种文件最多 5 份、单份 1 MiB，长期复验先另存，不能假设日志永久保留或已随 Git 上传。不同电脑的端点哈希也不同，不能据哈希自动绑定。

刷新频率分开核对：输入事件、设备查询、UI 发布、官方平滑是不同层。使用查询时间戳计算间隔，不能把 100 毫秒连接计时器当成电量频率。现有玄熊猫单端点快速查询为活动/可见约 1 秒、空闲约 5 秒，完整扫描周期独立；没有证据时不向其他品牌复制该策略或 P1 电压曲线。

### 启动与停止

1. 记录原始档位表、当前档、回报率、规则及恢复目标。
2. 抓官方软件时退出 FerrisPulse；测试自己实现时退出官方软件，避免客户端抢回复。
3. 仅捕获目标接收器地址，启用描述符注入；记录命令、时间、精确 PID、文件和总线地址，证据放 `tools/scratch/capture/`。
4. 需提升权限时隐藏启动辅助进程并保存 PID。确认进程存活、文件生成并开始有数据，才让用户操作。

命令模板：先替换本机接口、地址和绝对文件路径，尖括号不是可直接执行参数。

```text
USBPcapCMD.exe --capture --extcap-interface \\.\USBPcap<N> --fifo <绝对路径.pcap> --devices <设备地址> --inject-descriptors
```

停止自己启动的确切捕获进程，再解析文件；捕获中可能被独占，读失败不等于损坏。停止后验证描述符 VID/PID。空包先查接口、地址、驱动，不先改协议。不按名字批量结束其他捕获进程。

### 分批操作

| 批次 | 操作和目的 |
|---|---|
| 初始化 | 开官方软件，等电量/状态完成，分离查询与设置 |
| 选择已有档位 | A → B → A，约 3 秒间隔并记时；不同时改数值 |
| 回报率 | 逐项选官方软件实际提供的值，每次只改一个参数 |
| 修改板载 DPI | 另开一批，仅改一档的 X 或 Y，区分选档与改表 |
| 状态/连接 | 分批测有线、无线、充电、离线、重连，确定状态位与能力 |

官方软件没有目标上限时先确认模式、接收器和固件，不能直接猜高频命令。六档只有在设备真实提供时才逐档操作。

保留原始包和操作时间线，再提取脱敏十六进制 fixture 入测试。scratch 不随 Git 同步，交接注明抓包位置和备份情况。

## 5. 从报文建立协议模型

### 先确认传输

观察 Feature、Output SET_REPORT、Interrupt OUT 或其他控制传输；分别确认 Report ID 和 API/USB 数据长度是否包含 ID。不能因为原项目支持雷蛇，就套用其 Feature Report。

本轮玄熊猫是 Output SET_REPORT 加中断输入，代码使用 `DeviceIoControl(IOCTL_HID_SET_OUTPUT_REPORT = 0x000B0195)` 和 `ReadFile`；这不是新鼠标默认方案。

tshark HID payload 字段可能为空，可用 `-T json -x` 查看 `frame_raw`，按包头与传输长度定位数据。某些玄熊猫帧末 17 字节是报告，需验证布局后提取，不能通用地截每帧末 17 字节。PowerShell JSON 中 `frame.time_epoch` 可能是 ISO 时间，先查类型再转换，不盲目强转 double。

### 分层验证

1. 对齐操作时间、请求、回复，分离初始化、轮询、设置与 ACK。
2. 重复 A → B → A，找目标字段，区分命令、地址、长度、序号、数据、校验。
3. 多样本推导校验并用保留样本验证；校验通过不能证明数值含义正确。
4. 每个 Hz 保存官方包和回复。规律只作为假设，要开放的每档须独立写入回读；高档不能靠外推开放。
5. DPI 表确认档位数、X/Y、单位、扩展字节和最大长度；未知编码保留未知。
6. 区分读取 DPI、选择已有档位、改写每档数值、增删档位，验证哪项只开放哪项。
   电量亦需区分设备等级、原始电压、软件换算及历史平滑：同一等级可能长期不变，不能以“能读到一个百分比”证明更新正确。抓包同时记录官方显示与电压变化，查清型号标定、单位、端序、充电与缺失值处理；不能复制 P1 曲线到其他鼠标，也不能把官方缓存当作真实当前报文。
7. 先只读查询，再做最小可逆设置。ACK 后重新查询实际状态；回显不能单独证明设置生效。
8. 测超时、错误 ACK、断连、旧回复、错端点和未知值。不能吞异常、扩大延时或直接显示目标值掩盖失败。

协议表至少记录方向、传输、Report ID、长度、命令、地址、单位、校验、请求/回复样本、独立回读、端点/固件和未验证范围。

### 玄熊猫参考参数，禁止盲目套用

| 参数 | 本轮结论 |
|---|---|
| 设备/集合 | 3554/F5AC 4K；FF02 / Usage 2，Input/Output 17 字节，Report ID 08 |
| 校验 | 全 17 字节之和低 8 位为 55 |
| 回报率写入 | 命令 07，地址 0000，长度 02 |
| Hz → 值 / 校验字节 | 125→08/4D；250→04/51；500→02/53；1000→01/54；2000→10/45；4000→20/35 |
| 已有档位选择 | 地址 0004，线协议从 0 开始，UI 从 1 开始 |
| 读内存 | 命令 08，每次最多 10 字节；表长 12+4×档位数，最多 44 字节 |
| DPI 内容 | 基础编码 (byte+1)×50；非零扩展尚未验证 |
| 电量 / 在线 | 命令 04 / 03 |

P1 电量补充：命令 04 回复字节 6 为设备等级，7 为充电标记，8/9 为大端毫伏值。非充电时使用本型号已核实的电压曲线；充电/缺失电压保留等级，异常数据未知。官方还有历史平滑，显示百分比不必等于设备等级或单次插值。样本、边界及验证限制见 [缺陷 R6](metapanda-regressions.md)。

完整包与能力限制见 [使用指南](metapanda-guide.md)，fixture 见 [协议测试](../tests/test_metapanda_protocol.ps1)。两档时前 20 字节足够，不固定读取最大表拖慢手动反馈。F5A9 / F5AB 能力另列，不能按 F5AC 开放。

## 6. 接入代码的顺序与契约

| 层 | 接入方法 |
|---|---|
| 纯协议 | `src/Hardware/<Brand>Protocol.cs`，无 UI/真实硬件依赖，用报文 fixture 测试 |
| 传输/识别 | `<Brand>DeviceHelper.cs`，准确筛选、每路径串行、超时、ACK、回读 |
| 发现 | `DeviceManager.cs` 独立查询，通用/VGN 等排除已明确认领路径 |
| 能力/状态 | 按端点给操作/频率、表、X/Y、未知状态，不按全品牌统一最高能力 |
| 规则 | 复用现有语义和纯服务边界，显式接入品牌；现有 Metapanda 调度不自动支持任意鼠标 |
| UI | 手动、旧游戏、规则所有权、按钮、硬件提示、托盘、OSD 全部纳入路由 |
| 文档 | 新型号指南、证据/限制、测试入口及架构索引与代码一起维护 |

异步 Win32 I/O 保证缓冲区与 OVERLAPPED 在内核完成前有效。参考非托管内存、事件、超时、`CancelIoEx` 和完成排空；取消后未确认 I/O 结束不能释放。每端点串行，避免查询/设置互读回复；不使用无边界全局锁。

```text
端点与能力校验 → 取得写入/规则所有权 → 写入并匹配 ACK
→ 独立回读 → UI 线程发布完整确认状态 → 按钮/文字/托盘同步
→ 仅已接受的手动 DPI 结果触发 OSD
```

防止旧扫描覆盖新结果。锁忙表示稍后重试，不等于规则接管，不得丢成功反馈，详见 [缺陷 R1～R3](metapanda-regressions.md)。

规则接入须验证精确 exe/端点、实际基线、规则优先、离开恢复、表变化后匹配原 X/Y、断连/重连和正常退出。编辑器只编辑规则，预览不写硬件。按值输入匹配现有档位，与修改板载 DPI 明确分开。

## 7. 测试与实机验收

先用测试复现再修复。协议测已知包、错误长度/校验、未知值与 ACK；规则测编号/数值、重复值、X/Y 差异、表重排、不支持能力和恢复。

UI 测整条成功回调，特别是锁忙、对象替换、旧扫描、连续点击、规则接管、设备切换、失败不显示成功、OSD 开关和不抢焦点。硬件快、绘制快不能各自证明完整交互正确。

构建与测试命令、本轮 16 项基线见 [回归要求](metapanda-regressions.md)。`FERRISPULSE_TEST_ASSEMBLY` 指当前构建；检查正常输出，不能把 SKIP 或静态断言当完整运行。测试可能影响配置与 HKCU Run，先记录、隔离、还原。

至少实测：单击另一档 → 不补第二次 → 观察硬件/按钮/文字/OSD一致 → 切回。再测快速连续、规则接管/退出、断连/重连及每个开放回报率的写后回读。实际报告频率是单独测量项目，设置成功不能宣传已测得 4K / 8K。

桌面工具不可用时用用户单次操作加文字/原生窗口/USB 证据，明确谁点击。可访问对象测试不等于桌面自动点击。完成还原用户 DPI、回报率、规则和自启动。

## 8. 常见卡点

| 现象 | 优先检查 |
|---|---|
| USBPcap 服务运行但无接口 | 首装是否重启、接口枚举是否成功 |
| 官方软件能用，自有程序超时 | 集合/长度/ID、传输、两个客户端抢回复 |
| 空包或只有初始化 | 总线/地址变动、过滤目标、操作时间线 |
| ACK 正常但读数没变 | 回显不等于生效、语义/能力、回读端点 |
| 硬件变 UI 不变 | 回调丢失、对象替换、旧扫描、旧进程 |
| 第二次点击才高亮 | 锁忙被误当成接管而丢成功反馈 |
| 按钮正常无浮窗 | 公共通知、开关、状态是否接受、原生可见性 |
| 换电脑规则无效 | HID 与 exe 路径重绑，不自动转绑同型号 |
| 启动项变 powershell.exe | MainForm 构造副作用，恢复测试前状态 |
| 高 DPI/更高 Hz 未知 | 补单变量抓包，不套编码、不外推能力 |

## 9. 收工与交接模板

本次交接记录（2026-10-20）：远程 `https://github.com/Afang555/FerrisPulse.git`，分支 `MetapandaMouse05`，本轮修改起点为 `ac1081c`。用户已要求上传 GitHub，本次提交范围包含 4K、灵活规则、即时反馈、OSD 的代码、测试和适配文档。迁移应选择包含这些修改的提交，而非仅检出起点；以 `git log` 和远端分支实际状态核实版本。上传前已重新编译并完成 16 项相关回归，未重复进行新的实物点击验收，现场证据见缺陷记录。原始抓包仍需另外备份。

- 保存设备卡、操作时间线、协议表、脱敏 fixture、根因、测试、实测/未测项。
- 执行 `git diff --check` 和 `git status`，核对编码、相对链接与架构入口，保留原有未提交修改。
- 源码、测试、文档一并交接；exe/zip、完整抓包与 scratch 不提交源码仓库。明确未提交和忽略文件是否迁移，仅给仓库 URL 不够。
